Configuration

Run superline config to set up your prompt in the terminal: add, move and tweak widgets and recolor a theme while a live preview redraws the prompt after every key. Below the editor guide, the reference documents the config file itself, for when you'd rather edit the JSON by hand.

Open it

superline config edits ~/.config/superline/config.json, writing the default config first if there isn't one. --config <path> edits another file, and a symlinked config is saved through to the file it points at.

Save it

s saves the config and any theme you changed, and the next prompt picks them up—no reload. u undoes, U redoes, and q asks before dropping unsaved changes.

Keep your edits

Widgets, options and theme keys the editor doesn't know are kept exactly as written. e opens the file in $EDITOR and reloads it afterwards, and ? lists every key.

Add and arrange widgets

The Layout page lists each row, its left and right sides, and the widgets on them, top to bottom. The last row is the one you type on. a opens a filterable list of every widget and adds your pick just below the cursor, so on a side's heading it goes first.

Hand-editing the JSON

Everything the editor changes is plain JSON, and this reference documents the config file and every segment it can contain. Each entry lists the segment's options with their types and defaults, followed by examples. Each example pairs a screenshot with the JSON that produced it. Segments with several options have a minimal example and one that sets every option.

The config file

On first run superline writes a default config to ~/.config/superline/config.json. Changes take effect on the next prompt. superline config opens an interactive editor for it with a live preview of the prompt, and superline show --config <path> renders any other file.

KeyTypeDefaultDescription
themestring"rainbow"A path to a theme file; .json is optional, so "rainbow" is rainbow.json.
rowsarrayrequiredThe prompt's rows, top to bottom.
update.disablebooleanfalseStop the once-a-day check for a newer release and the notice it prints above the prompt.
update.autobooleantrueInstall a newer release in the background instead of only announcing it. Prompts drawn while it installs show how far it has got, and the first prompt on the new version says it was upgraded. Set to false to only be notified. Applies to prebuilt release binaries (not Homebrew, which updates with brew upgrade); a build from source keeps showing the notice until superline upgrade replaces it.

Every module can be written as a bare string or as an object with options, so "git" and { "git": {} } mean the same thing. Modules with required options must use the object form.

Besides its own options, every module except text, separator and padding takes padding: where each segment it draws gets a space beside its text. "small" adds none, "large" one on each side, and "left" or "right" one on that side only, as in { "git": { "padding": "small" } }. Without it, a module keeps its own spacing:

ModulePadding when unset
cwd, last_cmd_durationleft
cmd, shell, small_spacersmall
pythonlarge; venv label right
Every other modulelarge

The examples for each module show just that module's entry, to go in a row's left or right array; the screenshots include neighboring segments for context. Layout examples show a whole config, since they change how every segment around them is drawn.

Rows

Each row has a required left array and an optional right array of segments. Every row but the last is printed in full. The last row's right side is drawn by the shell's own right prompt (fish_right_prompt, zsh's RPS1, nushell's PROMPT_COMMAND_RIGHT), so it stays in place while you type. Bash and PowerShell have no right prompt, so on those shells the last row's right isn't shown.

Two rows, both sides
{
  "theme": "rainbow",
  "rows": [
    {
      "left": [
        { "cwd": { "max_length": 40, "wanted_seg_num": 3 } },
        "git"
      ],
      "right": [
        { "separator": "round" },
        "os",
        { "time": { "format": "%H:%M" } },
        { "padding": 0 }
      ]
    },
    {
      "left": ["shell", "cmd"],
      "right": [
        { "separator": "round" },
        "cargo",
        { "padding": 0 }
      ]
    }
  ]
}

Git & GitHub

git

The branch, then modified, untracked and staged counts, then commits ahead of and behind the upstream. A GitHub logo appears when the repo has a remote and links to its web page. A detached HEAD shows the short hash, followed by the branch it's the tip of, if any. When the repo has linked worktrees (git worktree add), their count follows the branch. Inside a linked worktree it reads index/count, such as 3/15, numbered in git worktree list order.

Status collection waits up to status_timeout_ms. If it takes longer, the last cached result is shown while a refresh finishes in the background; before anything is cached the segment says loading….

Languages

python, node, java and cargo each show their logo when the current directory belongs to a project, and add the version when one is pinned.

Versions come first from mise configs (mise.toml, .mise.toml, .config/mise/config.toml, .tool-versions and their .local variants), searched upwards from the current directory. A mise version beats one from a language-specific file, and is marked with a tools icon (Nerd Font md-tools, U+F1064), which themes can change or hide with each module's mise_icon. The global mise config in $HOME is ignored, so a global pin doesn't make the modules appear in every directory.

Claude Code

superline can also draw the status line at the bottom of Claude Code. superline install claude-code points statusLine in ~/.claude/settings.json at superline claude-code (another command is only replaced with --force) and writes the default layout to ~/.config/superline/claude-code.json. Or set it by hand: 

{ "statusLine": { "type": "command", "command": "superline claude-code", "padding": 0 } }

The layout file takes the same keys as the config file, and its theme names the same kind of theme file, so the prompt and the status line can share one. superline config --claude-code edits it with a preview drawn from sample session data. Every row is drawn in full; a row whose widgets all have nothing to show is left out.

Claude Code hands the command the session's data on stdin, and superline moves into the session's directory first, so cwd, git, the language modules and the rest describe where Claude is working. ai_usage with "provider": "claude" shows the five-hour and seven-day rate limits Claude Code reports instead of asking the CLI (Pro and Max plans, after the first response), and pr falls back to the pull request Claude Code reports, without a CI dot, until the gh lookup has one. cmd, last_cmd_duration, shell and jobs have no shell to read there.

The right side is aligned to $COLUMNS less a four-column margin, since Claude Code indents the status line. Change it with --margin <n>, or set the width with --columns <n>, in the command.

The claude_* widgets below draw only in the status line, and each is left out while Claude Code has nothing for it, such as no vim mode, no agent or no cost yet. The screenshots use sample data.

Themes

theme is a path to a theme file, and .json is optional: "rainbow" is rainbow.json. Paths starting with / are absolute; anything else is relative to the config directory. If the theme fails to load, superline falls back to rainbow.

superline comes with three themes, rainbow, simple and gruvbox. When the config names one of them and its file isn't in the config directory, superline uses the copy built into the binary and writes nothing. Editing a bundled theme on the Theme page and saving writes its file, which takes the built-in copy's place until it is deleted. The theme picker in superline config previews each theme on your own prompt before you switch, and the Theme page edits a theme file with a live preview.

A theme file has defaults, the fg and bg for anything a module doesn't set, and modules, per-module overrides. Most modules take fg and bg; some have more (git has staged_bg, cwd takes a bg_colors list, cmd has user_symbol). Every icon a widget draws is a string property that defaults to its usual glyph, such as git's branch_icon or battery's charging_icon; set one to "" to hide it. Colors are a color name or an ANSI 256-color code from 0 to 255. rainbow.json is a full example.

Every text color (fg, or a property ending in _fg) can also make its text bold, italic or underlined, with true/false properties named the same way: bold, italic and underline go with fg, and clean_bold, clean_italic and clean_underline with clean_fg. So "git": { "clean_bold": true } draws the branch name in bold while the working tree is clean. Separators and the rest of the prompt are never affected.

theme.json
{
  "defaults": { "fg": 153, "bg": 235 },
  "modules": {
    "cwd": {
      "path_fg": 255,
      "bg_colors": [23, 24, 25, 31, 37, 38]
    },
    "git": {
      "clean_bg": 30,
      "clean_fg": 255,
      "dirty_bg": 61,
      "dirty_fg": 255,
      "notstaged_bg": 97,
      "notstaged_fg": 255,
      "untracked_bg": 133,
      "untracked_fg": 255,
      "staged_bg": 29,
      "staged_fg": 255,
      "remote_bg": 238,
      "remote_fg": 250

    "cargo": { "fg": 255, "bg": 67 },

Commands

CommandWhat it does
superline install <shell>Append the prompt loader to the shell's config file. Safe to run more than once.
superline init <shell>Print the loader snippet instead.
superline configEdit the config in an interactive terminal editor: add, remove, reorder and configure widgets, and edit a custom theme's colours, with a live prompt preview. --config <path> edits another file, and --claude-code edits the Claude Code status line layout.
superline install claude-codePoint Claude Code's status line at superline. --force replaces another status line command.
superline claude-codeDraw the Claude Code status line from the session data on stdin. --sample draws sample data, to try a layout in the terminal.
superline clear-cachesWipe cached git status, PR lookups and AI usage so the next prompt starts cold.
superline upgrade [VERSION]Replace the binary with the latest (or given) release's prebuilt one. --check only reports whether one is available. Also available as superline update. Homebrew installs use brew upgrade superline instead.
SUPERLINE_DEBUG=1Print a per-module timing report to stderr after each render.
